# sim — AGENTS.md

> Read the root `AGENTS.md` first. Owner C · kind harness (may import any module; nothing may import sim).

## Purpose
Lets the whole system run on one laptop with no hardware, glasses or real users:
- **Twins** (`nodes/`, run by `run.py`): every source has one. Robot twins publish the **same MQTT topics** as the
  real devices; app twins send the **same HTTPS requests** as the real apps. Everything they produce has
  `sim: true` and keeps the real `source` name.
- **History** (`patients/`, `seed_demo.py`): 8 synthetic 30-day patients covering every consensus state, seeded
  into the cloud. Generated by `kaiku_cloud.jobs.synth`, so the cloud simulation uses the same generator.

## Consumes (topics/endpoints)
See the twin table (Map). Seeder: `GET /healthz`.

## Emits (topics/endpoints)
See the twin table (Map). Seeder: `POST /v1/events` (obs only, `sim: true`), `POST /v1/admin/recompute`,

**Auto mode** acts like a user, following the hub's dial protocol (`hub/AGENTS.md` → Invariants):
someone walks up after 3 s → the hub starts the ritual · `dial started` → three answers (mood, energy, sleep): turn the
ear knob, then press (`[robot] dial_input`; `--dial button` = press the button n times) · `drum started` → tap at `--tempo` · `obs/drum_session` → stop, answer the post-activity
mood · `phq9 started` → nine presses (item 9 always 0) · during `breathe` the PPG's RSA grows (RMSSD rises) ·
glasses walk, laptop session + Mac hour, phone morning (watch summary + weather check) + firefly once at start,
then every `--every` s.

Demo patients (ids, intended states): `cloud/AGENTS.md` → Run with sim. Their end states are pinned by cloud tests.

## Extension points
- **New hardware node:** `nodes/<node>_sim.py` publishing exactly what the firmware publishes; add it to `run.py`'s
  node table and to the `sim` entry in `modules.toml`.
- **New source (4th touchpoint):** an HTTPS twin built on `http_source.py`, plus scenario coverage in
  `kaiku_cloud.jobs.synth`.
- **New scenario:** add it to the synth cohort with its intended state; the cloud test asserts it lands there.

## Invariants
- A twin never emits anything the real device wouldn't (same topics, same payload shapes, `sim: true`).
- HTTP twins fail soft when the cloud is down (timeout + retry, log, keep running).
- Keyboard keys are documented once: in `run.py`'s docstring and in "Run standalone" below.

## Run standalone
`make sim` (all six twins, auto) · `make sim NODES=head,sensors` · `make sim ARGS=--keyboard` (keys: `t` tap,
`[`/`]` ear, `e` press ear, `b` press head button, `p` arrive/leave, `s` start ritual, `x` long-press top button = manual safety trigger,
`2` second person in view, `f` friend presses lamp, `w` glasses walk, `l` laptop session, `9` laptop PHQ-9, `m` Mac hour (screen activity +
firefly), `o` phone morning (watch summary + weather check), `q` quit).
Single twin: `uv run python -m sim.nodes.head_sim --tempo 110` · `uv run python -m sim.nodes.laptop_sim --once --phq9-item9`
· `uv run python -m sim.nodes.phone_sim --once [--no-watch]`.
Cohort without network: `uv run python -m sim.patients [--jsonl logs/patients.jsonl]`.

## Run with sim
`make broker` · `make cloud-local` · `make seed` · `make sim` · `make hub` · `make tail`.
`make seed ARGS=--reset` wipes simulated data and re-anchors history to today; `KAIKU_CLOUD_URL=https://<modal-url> make seed`
seeds the deployed cloud.

## Config & env
`MQTT_*`, `KAIKU_HOME_ID`, `KAIKU_CLOUD_URL` (default `http://localhost:8000`), `KAIKU_HOME_TOKEN` (Bearer for the
HTTPS twins and the seeder), `KAIKU_ADMIN_TOKEN` (seeder admin calls). `KAIKU_RITUAL_DRUM_S` etc. shorten the auto
drum. `run.py` flags: `--every`, `--phq9`, `--phq9-item9`, `--tempo`, `--mood`, `--arrive-after`, `--two`.
`sensors_sim` alone: `--no-faces`, `--two`.

## Health signal
MQTT twins heartbeat on `health/<node>` with `details.sim = true`. HTTPS twins log `posted` / `cloud_unreachable`.
`seed_demo` exits non-zero if the cloud is unreachable or rejects anything.

## Tests
`uv run pytest sim/tests` (PPG heart rate + RSA, approach curve, face boxes grow on approach / two people, head dial/drum/post-mood protocol and PPG gating on
a real broker, glasses/laptop envelopes + auth via `httpx.MockTransport`, fail-soft when the cloud is down). The
generator and every demo patient's end state are tested in `cloud/tests`.

## Known issues
- Pan is cosmetic (no motor physics). PPG has no motion artefacts — use recorded fixtures for quality-gate tests.
- The laptop twin's features are plausible random numbers, not computed from audio/video.
- Phone/Mac twins stand in for `apps/apple` until it exists (`modules.toml [planned_producers]`).
- Simulated drift is one model (a ramp across signals); real drift will be messier.
